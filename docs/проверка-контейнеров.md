# Результаты проверки в контейнерах

Проверка проведена 30 сентября 2026 года. Репозиторий подключался к каждому контейнеру только для чтения. В контейнерах предварительно устанавливался `zsh`, затем выполнялся `install.sh`, запускалась интерактивная оболочка и выполнялся `uninstall.sh`.

| Образ | Архитектура контейнера | Результат |
| --- | --- | --- |
| Debian 12 | arm64 | Установка, запуск zsh и удаление пройдены |
| Debian 13 | arm64 | Установка, запуск zsh и удаление пройдены |
| Ubuntu 24.04 | arm64 | Установка, запуск zsh и удаление пройдены |
| Ubuntu 26.04 | arm64 | Установка, запуск zsh и удаление пройдены |
| Fedora 43 | arm64 | Установка, запуск zsh и удаление пройдены |
| Fedora 44 | arm64 | Установка, запуск zsh и удаление пройдены |
| Arch Linux rolling | amd64 под эмуляцией | Установка, запуск zsh и удаление пройдены |

Во всех сценариях проверялось наличие сгенерированного bundle Antidote, доступность команды `zplugin-update` в новой интерактивной zsh, удаление маркера проекта из `.zshrc`, сохранение посторонней строки и восстановление исходного `starship.toml` из резервной копии.

Для Arch Linux контейнеру требовалась настройка `DisableSandbox` в `pacman.conf`: встроенная seccomp-песочница pacman не работает в используемой Docker-среде. Настройка применялась только внутри одноразового контейнера; установщик проекта её не меняет. Причина и параметр соответствуют [официальной документации pacman](https://man.archlinux.org/man/core/pacman/pacman.conf.5.en).

Отдельно обе конфигурации Starship (`config/starship.toml` и `config/starship-compact.toml`) разобраны командой `starship explain` в Debian 12; команда завершилась без предупреждений и ошибок.

## Повторная установка

В Debian 12 отдельно выполнена последовательность `install.sh` два раза подряд с тем же временным HOME. После второго запуска осталось по одному маркерному блоку и записи на каждую цель, количество резервных копий не увеличилось, состояние владения исходным `starship.toml` осталось прежним. Повторно загружать zoxide установщик больше не стал: перед проверкой зависимостей скрипт добавляет уже существующий `~/.local/bin` в свой `PATH`.

Эти результаты не заменяют проверку macOS. Визуальный вид prompt в терминале и откат после искусственной ошибки копирования в этой сессии не проверялись.
