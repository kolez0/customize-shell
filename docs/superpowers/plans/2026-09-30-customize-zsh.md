# План реализации Customize zsh

> **Статус:** основная реализация выполнена. Контейнерные сценарии установки, запуска zsh и удаления пройдены для всех Linux-выпусков из матрицы; повторная установка и откат после ошибки дополнительно проверены в Debian 12. Полная установка, загрузка конфигурации и проверка горячих клавиш выполнены на macOS 26.5.2. Результаты отражены в `docs/проверка-контейнеров.md` и `docs/проверка-macos.md`. Визуальная проверка prompt в терминале остаётся незавершённой.

Отметка `[x]` означает, что соответствующий файл или поведение реализованы; она не заменяет запуск на целевой системе.

**Цель:** Реализовать переносимый комплект конфигурации zsh с Antidote, Starship и безопасными установкой, обновлением и удалением на согласованных платформах.

**Архитектура:** Установщик на POSIX `sh` проверяет ОС и зависимости, устанавливает недостающие утилиты, затем копирует конфигурацию из репозитория в XDG-каталоги и управляет только помеченным блоком `~/.zshrc`. Конфигурация zsh разделена на небольшие файлы, загружает статический bundle Antidote без сети и запускает Starship из отдельного файла.

**Технологии:** POSIX `sh`, zsh, Antidote, TOML для Starship, Homebrew, `apt`, `dnf`, `pacman`, Git и поддерживаемые CLI-утилиты.

**Спецификация:** `docs/specification.md`

## Глобальные ограничения

- Поддерживаемые платформы: macOS 15 и новее на Apple Silicon с Homebrew; Debian и Ubuntu с `apt`; Fedora с `dnf`; Arch Linux с `pacman`.
- Поддерживаются только версии macOS и выпуски Debian, Ubuntu и Fedora, для которых поставщик ОС предоставляет обновления безопасности на момент выпуска проекта; для Arch Linux поддерживается актуальная rolling-release-система.
- zsh должен быть предварительно установлен; установщик проверяет его наличие, но не устанавливает и не меняет оболочку пользователя.
- Установщик реализуется на POSIX `sh`, чтобы работать на целевых macOS и Linux без дополнительного runtime.
- Установщик копирует управляемые файлы; симлинки не используются.
- Файлы проекта размещаются в `${XDG_CONFIG_HOME:-$HOME/.config}/customize-zsh/`, а `starship.toml` — в `${XDG_CONFIG_HOME:-$HOME/.config}/starship.toml`.
- Antidote клонируется из `https://github.com/mattmc3/antidote.git` в `${ZDOTDIR:-$HOME}/.antidote`.
- Обычный запуск интерактивной оболочки не должен выполнять сетевые запросы или обновлять плагины автоматически.
- Перед полной заменой отличающегося существующего управляемого файла создаётся резервная копия; `~/.zshrc` целиком не заменяется и не копируется.
- Документация хранится в `docs/` и ведётся на русском языке; корневой `README.md` — единственное исключение и краткая главная страница проекта.

## Файлы и ответственность

- `install.sh` — обнаружение платформы, проверка предварительных условий, установка зависимостей, установка Antidote, копирование файлов и откат при ошибке.
- `uninstall.sh` — безопасное удаление подключённой конфигурации и восстановление управляемых файлов.
- `config/zsh/rc.zsh` — главный файл конфигурации, подключаемый помеченным блоком из `~/.zshrc`.
- `config/zsh/` — разделённые модули базовых настроек, истории, completions, плагинов, утилит и локальных интеграций.
- `config/zsh/.zsh_plugins.txt` — декларативный список плагинов Antidote.
- `config/zsh/tools.zsh` — интеграции fzf, zoxide, fd, bat, eza, ripgrep и пользовательские алиасы.
- `config/starship.toml` — шаблон согласованного prompt; при установке копируется в `${XDG_CONFIG_HOME:-$HOME/.config}/starship.toml`.
- `config/starship-compact.toml` — компактный вариант без языковых версий; копируется в `${XDG_CONFIG_HOME:-$HOME/.config}/customize-zsh/starship-compact.toml`.
- `README.md` — краткая главная страница проекта со ссылками на русскоязычные руководства.
- `docs/` — инструкции установки, платформенная матрица пакетов и источников, обслуживание, удаление и восстановление.

## Основные риски для проверки

- `~/.zshrc` содержит произвольные сторонние строки или блок проекта повреждён — проверить, что изменяется только корректно распознанный помеченный блок.
- XDG-пути содержат пробелы, отсутствующие каталоги или уже имеющиеся файлы — все операции с путями должны корректно цитироваться, резервирование должно предшествовать замене.
- Установка обрывается на середине копирования — целые файлы восстанавливаются, созданные файлы удаляются, состояние `.zshrc` возвращается к исходному.
- Утилита доступна под `fdfind` или `batcat` — оболочка использует её через команды `fd` и `bat`, не создавая глобальных симлинков.
- В системном репозитории нет подходящего пакета — применяется только официальный upstream-канал, документированный самим проектом утилиты; при отсутствии такого канала конфигурационные файлы не меняются.

### Задача 4: Предварительные проверки и установка зависимостей

**Файлы:**
- Создать: `install.sh`
- Создать: `docs/установка.md`
- Создать: `docs/поддерживаемые-платформы.md`

**Интерфейсы:**
- POSIX `sh` функции: `detect_platform`, `check_prerequisites`, `ensure_dependency`, `install_antidote`.
- Пакетный backend выбирается только из соответствия ОС: Homebrew, `apt`, `dnf`, `pacman`.
- Homebrew применяется для macOS; `apt`, `dnf`, `pacman` используют имена пакетов, документированные upstream и доступные для текущего поддерживаемого выпуска.
- Для Starship на Linux используется пакет дистрибутива только там, где актуальная официальная документация Starship явно перечисляет поддерживаемый выпуск; иначе загружается официальный установщик с `starship.rs` во временный файл.
- Для Debian/Ubuntu: `git`, `fzf`, `fd-find`, `bat`, `ripgrep` — системные пакеты при наличии; `eza` — подписанный APT-источник, указанный официальной инструкцией eza; `zoxide` — официальный установщик upstream, так как проект отмечает Debian/Ubuntu-пакеты как устаревшие.
- Для Fedora: `git`, `fzf`, `fd-find`, `bat`, `eza`, `ripgrep`, `zoxide` — пакеты Fedora; Starship — официальный установщик `starship.rs`, без добавления Copr-репозитория.
- Для Arch Linux: `git`, `starship`, `fzf`, `fd`, `bat`, `eza`, `ripgrep`, `zoxide` — пакеты официальных репозиториев Arch.
- Для macOS: все перечисленные утилиты устанавливаются пакетами Homebrew.
- Shell-скрипт upstream скачивается во временный файл с официального домена и запускается через `sh` после успешной загрузки; конвейер `curl | sh` не используется.

### Задача 5: Идемпотентное копирование, резервирование и откат

**Файлы:**
- Изменить: `install.sh`

**Интерфейсы:**
- Маркеры `.zshrc`: `# >>> customize-zsh >>>` и `# <<< customize-zsh <<<`.
- Манифест владения `${XDG_CONFIG_HOME:-$HOME/.config}/customize-zsh/install-manifest` содержит по одной фиксированной относительной цели на строку.
- Для каждой цели sidecar-файл в `ownership/` хранит состояние `created`, `preexisting` или `backup:<путь>`.
- Резервные копии лежат в `${XDG_CONFIG_HOME:-$HOME/.config}/customize-zsh/backups/` и получают UTC-метку времени, PID и при совпадении имени порядковый суффикс.
- Установщик и удалитель принимают только цели из встроенного списка; перед изменениями удалитель сверяет manifest и все записи ownership в обоих направлениях.

- [x] Создать/обновить только маркерный блок `.zshrc`, указывающий на `${XDG_CONFIG_HOME:-$HOME/.config}/customize-zsh/zsh/rc.zsh`; сохранять все внешние строки.
- [x] Генерировать статический Antidote bundle временным процессом zsh и устанавливать конфигурацию только после успешной генерации.

## Границы плана и ручная приемка

Реализация не добавляет отдельную автоматическую тестовую систему. Приёмка проводится вручную на одном окружении каждой поддерживаемой ОС: установка, повторный запуск, запуск новой интерактивной zsh, проверка prompt/интеграций, искусственная ошибка копирования, откат и удаление с сохранением чужих строк `.zshrc`.
