# Обновление и удаление

## Обновить файлы конфигурации

В каталоге клонированного проекта получите изменения и запустите установщик снова:

```sh
git pull --ff-only
./install.sh
```

Установщик копирует только изменившиеся файлы. Перед заменой уже существующего управляемого файла он создаёт датированную резервную копию и сообщает её путь. Файл `local.zsh`, если он уже существует в пользовательской конфигурации, повторно не заменяется. Остальные строки `~/.zshrc` сохраняются.

## Обновить Antidote и плагины

Выполните в интерактивной zsh:

```zsh
zplugin-update
```

Команда обновляет Antidote и плагины, затем атомарно пересоздаёт статический bundle. При ошибке предыдущий bundle остаётся на месте. Запуск оболочки не выполняет сетевых запросов. Чтобы синхронизировать саму конфигурацию из Git-репозитория, повторно запустите `install.sh`.

## Удалить конфигурацию

Из каталога проекта запустите:

```sh
./uninstall.sh
```

Скрипт удаляет только корректный помеченный блок из `.zshrc`, восстанавливает управляемые файлы из сохранённых копий либо удаляет файлы, которые проект создал впервые. Исходные файлы, совпадавшие с проектной конфигурацией до установки, остаются нетронутыми. Резервные копии и Antidote сохраняются; установленные системные утилиты не удаляются.

## Восстановить файл вручную

В сообщении `install.sh` указан путь к созданной резервной копии. Скопируйте нужный файл из каталога `${XDG_CONFIG_HOME:-$HOME/.config}/customize-zsh/backups/` обратно в указанный конфигурационный путь. Не удаляйте резервную копию, пока не убедитесь, что восстановленная оболочка работает как ожидается.

Локальные машинные настройки размещайте в `${XDG_CONFIG_HOME:-$HOME/.config}/customize-zsh/zsh/local.zsh`; установщик создаёт этот файл только при отсутствии и не заменяет его при повторном запуске.
